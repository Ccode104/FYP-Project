# Implementation Plan: Video Section Indexing with Transcript Processing

## Feature Analysis

### Already Implemented ✅

1. **Database Schema** (`backend/prisma/schema.sql`)
   - `video_sections` table with `(id, video_id, start_time, end_time, title, summary, transcript_snippet)`
   - `video_transcripts` table with `(id, video_id, full_transcript, word_timestamps, language)`
   - `video_quiz_questions` has `section_id` foreign key (nullable for migration)

2. **Backend Controllers** (`backend/controllers/videosController.js`)
   - `processVideoTranscript(videoId)` function (lines 1052-1151):
     - Checks for existing transcript
     - Generates dummy transcript (placeholder)
     - Uses Groq SDK to divide transcript into 4-8 logical sections
     - Stores transcript and sections in database
   - `getVideoSections()` endpoint (lines 1153-1176)
   - `getVideoTranscript()` endpoint (lines 1178-1203)
   - Helper functions: `generateDummyTranscript()`, `generateDummySections()`

3. **Frontend - Student View** (`frontend/src/pages/student/VideoPlayerPage.tsx`)
   - Loads sections via `GET /api/videos/:id/sections`
   - Displays sections in sidebar "Sections" tab
   - Shows current section based on playback time
   - Links quiz questions to sections

4. **Frontend - Teacher View** (`frontend/src/pages/teacher/VideoQuizEditor.tsx`)
   - Loads sections on mount
   - Section dropdown in "Add Question" form (line 338-352)
   - Questions saved with `section_id` (line 215)
   - Questions grouped/displayed by section

5. **Configuration**
   - `GROQ_API_KEY` configured in `backend/.env` (line 18)
   - `groq-sdk` in dependencies (`backend/package.json` line 32)

### Missing / Needs Implementation ❌

1. **Automatic Trigger** - `processVideoTranscript()` is NOT called automatically after video upload
   - `uploadVideo()` (Cloudinary) - No trigger
   - `uploadVideoToDrive()` (Drive) - No trigger
   - Currently requires manual execution via `fix_drive_upload.js` script

2. **Real Transcript Extraction** - `processVideoTranscript()` uses dummy transcript
   - Should extract actual audio from video file
   - Should use speech-to-text (Whisper, Google STT, or similar)
   - Currently only generates placeholder sections

3. **Processing Status Feedback** - No way to know if sections are ready
   - Frontend shows empty sections until processing completes
   - No loading state or retry mechanism

4. **API Coverage** - Frontend uses direct `apiFetch` instead of typed methods
   - Missing API functions in `frontend/src/features/videos/api/videos.ts`

## Implementation Plan

### Phase 1: Automatic Transcript Processing Trigger

**File: `backend/controllers/videosController.js`**

- After successful video upload in `uploadVideo()` (Cloudinary), call `processVideoTranscript(videoId)` asynchronously
- After successful video upload in `uploadVideoToDrive()` (Drive), call `processVideoTranscript(videoId)` asynchronously
- Ensure `processVideoTranscript` doesn't block upload response (fire-and-forget)
- Wrap in try-catch to avoid breaking upload if processing fails

### Phase 2: Real Transcript Extraction (Optional Enhancement)

**Dependencies to add:**

- Install `@whispercpp/whisper` or similar, or use external API

**Approach A: Whisper.cpp Integration (local)**

- Extract audio from video using `ffmpeg` (system binary)
- Run Whisper model on audio file
- Get transcript with word-level timestamps

**Approach B: External API (simpler)**

- Use OpenAI Whisper API or AssemblyAI
- Requires API key and network call

**Decision:** For FYP demo, Approach A with a small model or pre-generated dummy may suffice. But user requirement says "extract the transcript", implying real extraction.

### Phase 3: Improve Groq Section Division

- Ensure `processVideoTranscript` handles long transcripts with proper chunking
- Validate JSON response from Groq with fallback
- Log section counts and timestamps for debugging

### Phase 4: Frontend API Methods

**File: `frontend/src/features/videos/api/videos.ts`**

Add:

```typescript
export async function getVideoSections(videoId: number): Promise<{ sections: VideoSection[] }>;
export async function getVideoTranscript(videoId: number): Promise<{ transcript: string }>;
```

Define `VideoSection` interface.

### Phase 5: Processing Status UI

**VideoPlayerPage enhancements:**

- Show "Processing transcript..." banner if sections empty but video exists
- Auto-refresh sections when ready (polling or WebSocket)

**VideoQuizEditor enhancements:**

- Disable section dropdown until sections loaded
- Show loading indicator while sections processing

### Phase 6: Error Handling & Edge Cases

- Handle duplicate processing (idempotency)
- Handle videos without `drive_file_id` gracefully
- Retry mechanism for failed Groq calls
- Database rollback on partial failures

---

## Implementation Order ( Recommended )

1. **Add automatic trigger** in both upload controllers (quick win, no new deps)
2. **Add typed API methods** for sections/transcript in frontend
3. **Improve UI feedback** for processing status
4. **Implement real transcript extraction** (if required, biggest effort)
5. **Test end-to-end** with actual video upload
6. **Polish** - error messages, loading states, logging
